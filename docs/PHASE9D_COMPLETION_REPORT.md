## 1. Executive Summary

Phase 9D delivers the consolidated Case Investigation Workspace and Evidence-Grounded FinSure Investigator for the FinSure platform. It connects the frontend directly to the canonical Phase 8 Case Management and Investigation API contracts.

The implementation strictly maintains:
1. **Assistive AI Boundary:** The FinSure Investigator is strictly assistive and non-autonomous. It evaluates read-only evidence and synthesizes explanatory narratives. It possesses zero capability or permission to mutate case records, change risk scores, modify thresholds, or confirm fraud verdicts.
2. **Authoritative Evidence Grounding:** Every statement generated by the Investigator must cite explicit, recorded evidence IDs (e.g. `[E1]`, `[E2]`). All citations in the narrative are interactive and link directly to verified evidence records in the Evidence Binder.
3. **Zero-Deletion Immutability:** Evidence records are immutable and can never be deleted from the database. A record may only be marked as `withdrawn` with a mandatory reason code and timestamp.
4. **State Machine Canonical Authority:** Case transitions strictly mirror the backend state machine. `closed` is terminal.
5. **Four-Eyes Policy:** Dismissing a `CRITICAL` priority case (or risk score $\ge 90$) requires co-authorization from a second analyst or compliance supervisor (`approved_by`).
6. **Cryptographic Tamper-Detection:** SHA-256 hash chains verify the integrity of stored artifacts, serving as proof that the record has not been tampered with.

## 4. Key Workflows Implemented

### 1. Alert $\to$ Incident $\to$ Case Escalation
From `AnalystIncidentDetailPage.tsx`, clicking **"Open Case Docket"** triggers `POST /api/v1/cases` with `{ incident_id: incident.incident_id }`. The backend idempotently returns the existing docket or provisions a new canonical Case entity, pre-seeding evidence items (`E1` transaction, `E2` SHAP features, `E3` device telemetry, `E4` autoencoder anomaly, `E5` graph link). The UI automatically routes to `/analyst/cases/:case_id`.

### 2. Evidence Binder & Zero-Deletion Rule
The Evidence Binder allows analysts to inspect, filter, search, and register new evidence. When an analyst clicks "Withdraw", a mandatory withdrawal justification is enforced. The item is marked with `withdrawn_at` and `withdraw_reason`, displayed with distinct strike-through styling, and removed from the active Investigator citation pool without mutating or deleting raw historical data.

### 3. FinSure Investigator (Plan $\to$ Examine $\to$ Report)
Clicking **"Run Investigation"** triggers `POST /api/v1/cases/:id/investigate`. The UI renders:
- **Plan:** Enumerates the step-by-step reasoning strategy.
- **Examine:** Lists all read-only sandbox tools executed with status indicators.
- **Report:** Formatted narrative where every `[E1]`, `[E2]` citation is an interactive button that, when clicked, switches to the Evidence Binder tab and highlights the referenced evidence record.
- **Interactive Claim Validator Sandbox:** An interactive workbench where analysts can test arbitrary sentences against the case evidence store live.

### 4. Canonical State Adjudication & Four-Eyes Policy
The state transition modal dynamically presents only valid transitions from the current state:
- `new` $\to$ `under_investigation`
- `under_investigation` $\to$ `escalated`, `confirmed_fraud`, `dismissed`
- `escalated` $\to$ `under_investigation`, `confirmed_fraud`, `dismissed`, `closed`
- `confirmed_fraud` $\to$ `closed`
- `dismissed` $\to$ `closed`
- `closed` $\to$ *Terminal (all controls disabled)*
- Mandatory `reason_code` and explanatory `note` are enforced for `dismissed` and `escalated`.
- Dismissing a `CRITICAL` priority case requires co-authorization from a second user (`approved_by !== actor_id`).

### 5. Evidence Pack ZIP Export
Clicking **"Export Evidence Pack (ZIP)"** triggers `GET /api/v1/cases/:id/evidence-pack`, downloading an official cryptographic bundle containing `manifest.json`, `case_summary.json`, `evidence_records.json`, `audit_events.json`, `case_transitions.json`, and `investigation_report.txt`.

## 6. Known Limitations
1. **Interactive LLM Streaming:** The FinSure Investigator currently runs on the deterministic `TemplateInvestigatorAdapter`, which guarantees 100% groundedness and zero hallucination risk. An interface is provided for external LLMs (e.g. Ollama/Llama 3), with fallback protection on ungrounded claims. Streaming text generation is intentionally not faked on the frontend.
2. **Persistence Backend:** In this development phase, cases and evidence are stored in thread-safe SQLite repositories (`data/finsure_cases.db`). Multi-node clustering in production will connect to PostgreSQL using existing schema definitions.
