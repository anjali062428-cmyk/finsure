# FinSure Investigator Architecture & Governance

## 1. Operating Philosophy: Assistive, Calm & Non-Autonomous
The **FinSure Investigator** is an evidence-grounded AI copilot designed specifically for fraud analysts. In accordance with the FinSure brand guidelines and security rules:
- **Assistive Only:** It never autonomously decides fraud verdicts, alters transaction states, blocks users, or mutates risk policies.
- **Calm Branding:** Named strictly "FinSure Investigator" across all internal systems and interfaces—never "Autonomous AI" or "AI Judge".
- **Code Computes, Models Narrate:** Counts, amounts, times, and link statistics are computed by deterministic code tools. The narration layer merely renders sentences.
- **Human Authority:** The human fraud analyst retains sole decision authority.

---

## 2. Plan -> Examine -> Report Workflow

```
[ALERT / CASE]
      │
      ▼
   1. PLAN       (Deterministic sequence of 7 investigative checks)
      │
      ▼
   2. EXAMINE    (Execute read-only tools via strict Security Sandbox)
      │
      ▼
   3. REPORT     (Synthesize narrative citing [E1], [E2] evidence IDs)
      │
      ▼
   4. VALIDATE   (ClaimValidator checks groundedness & tone)
      │
      ├── Passed ──► Persist run to `investigation_runs`
      └── Failed ──► Automatic fallback to deterministic Template Adapter
      │
      ▼
[HUMAN ANALYST REVIEWS & DECIDES]
```

## 3. Pluggable Narration Adapters
FinSure supports pluggable generation backends:

1. **`TemplateInvestigatorAdapter` (Default):**
   - 100% deterministic code synthesis.
   - Guaranteed zero hallucination risk and 100% grounded citations.
   - Produces structured sections: Case Summary, Observed Evidence, Risk Indicators, Missing Evidence, Recommended Questions, and Advisory Findings.

2. **`InvestigatorModelAdapter` (Extensible for Local/Hosted LLMs):**
   - Can interface with local models (e.g., Ollama / Llama 3) or hosted APIs.
   - **PII Masking:** Passes only masked identifiers (e.g., `al***@example.com`, `+91 *** *** 3210`).
   - **Prompt Injection Defense:** Free text is enclosed inside `<UNTRUSTED_DATA>` boundaries.
   - **Automatic Fallback:** If the model introduces an ungrounded number or invalid citation, `ClaimValidator` triggers an instant, seamless fallback to `TemplateInvestigatorAdapter`.

## 4. Run Persistence (`investigation_runs`)
Every investigation run is audited in SQLite/PostgreSQL:
```sql
CREATE TABLE investigation_runs (
    run_id TEXT PRIMARY KEY,
    case_id TEXT NOT NULL,
    plan_json TEXT NOT NULL,
    tool_calls_json TEXT NOT NULL,
    findings_json TEXT NOT NULL,
    report_text TEXT NOT NULL,
    provider TEXT NOT NULL,
    model TEXT NOT NULL,
    prompt_hash TEXT NOT NULL,
    validator_passed INTEGER NOT NULL,
    groundedness_score REAL NOT NULL,
    unsupported_claims_json TEXT NOT NULL,
    latency_ms REAL NOT NULL,
    created_at TEXT NOT NULL,
    FOREIGN KEY (case_id) REFERENCES cases(case_id)
);
```
Every report exported or viewed displays:
> *"Generated by FinSure Investigator (assistive only). Human analyst retains sole decision authority."*
