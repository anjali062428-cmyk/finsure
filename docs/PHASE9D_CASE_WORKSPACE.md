# FinSure — Phase 9D Case Investigation Workspace Architecture

## 1. Overview & Operational Philosophy

The FinSure Case Investigation Workspace (`/analyst/cases` and `/analyst/cases/:id`) transforms the Phase 8 Case Investigation backend into an institutional-grade, evidence-grounded forensic workbench.

### Foundational Principles
1. **Assistive AI Boundary:** The FinSure Investigator is strictly assistive and non-autonomous. It evaluates read-only evidence and synthesizes explanatory narratives. It never makes automated fraud verdicts, modifies risk scores, alters thresholds, or blocks transactions.
2. **Authoritative Evidence Grounding:** Every statement generated by the Investigator must cite explicit, recorded evidence IDs (e.g. `[E1]`, `[E2]`). Statements without citations or with invalid citations fail validation and are marked as ungrounded.
3. **Zero-Deletion Immutability:** Evidence records are immutable and can never be deleted from the database. A record may only be marked as `withdrawn` with a mandatory reason code and timestamp.
4. **State Machine Canonical Authority:** Case transitions strictly mirror the backend state machine. `closed` is terminal.
5. **Four-Eyes Policy:** Dismissing a `CRITICAL` priority case (or risk score $\ge 90$) requires co-authorization from a second analyst or compliance supervisor (`approved_by`).
6. **Cryptographic Tamper-Detection:** SHA-256 hash chains verify the integrity of stored artifacts, serving as proof that the record has not been tampered with.

## 3. Case State Machine & Canonical Lifecycle

The case state machine adheres to the following transition graph:

| Current Status | Allowed Target Statuses | Mandatory Requirements |
|---|---|---|
| `new` | `under_investigation` | None |
| `under_investigation` | `escalated`, `confirmed_fraud`, `dismissed` | Reason code and note required for `escalated` and `dismissed` |
| `escalated` | `under_investigation`, `confirmed_fraud`, `dismissed`, `closed` | Reason code and note required for `dismissed`; Four-Eyes check for critical |
| `confirmed_fraud` | `closed` | High-impact confirmation prompt |
| `dismissed` | `closed` | High-impact confirmation prompt |
| `closed` | *None (Terminal)* | All state modification controls disabled |

### Four-Eyes Co-Authorization Rule
When transitioning a case to `dismissed` where `priority === 'CRITICAL'` or `risk_score >= 90`:
- The frontend modal renders a dedicated warning banner: *"Four-Eyes Policy Enforcement: Dismissing a CRITICAL priority case requires co-authorization from a second analyst or compliance supervisor."*
- Collects an `approved_by` user identifier.
- Enforces that `approved_by.toLowerCase() !== current_user.user_id.toLowerCase()`.
- The backend validates this condition independently; requests violating this rule are rejected with `HTTP 400 Bad Request`.

## 4. Evidence Binder & Zero-Deletion Rule

The Evidence Binder displays all immutable evidence records tied to the case docket:
- **Evidence Types:**
  - `transaction`: Payment rail telemetry (amount, channel, timestamp)
  - `device`: Device fingerprint, hardware integrity, and IP address
  - `location`: Geolocation coordinates and velocity metrics
  - `shap_reason`: Top XGBoost feature contribution weights
  - `autoencoder_anomaly`: Reconstruction error vs. baseline threshold $\tau$
  - `graph_link`: Trinetra ego-network connectivity and mule hub degree
  - `user_profile`: Historical baseline behavior
  - `external_file`: Sworn affidavits, bank statements, regulatory filings
  - `analyst_note`: Internal forensic commentary
  - `customer_report`: Grievance filings and "Not Me" dispute telemetry
- **Zero-Deletion Enforcement:**
  - Clicking "Withdraw" opens a modal requiring a mandatory reason (minimum 3 characters).
  - The record is marked with `withdrawn_at` and `withdraw_reason`.
  - Withdrawn items are rendered with distinct strike-through styling and excluded from the active Investigator citation pool.

## 5. FinSure Investigator Pipeline

The FinSure Investigator panel organizes copilot activity into three clear stages:
1. **Plan:** Enumerates the step-by-step forensic reasoning plan.
2. **Examine:** Displays read-only tools executed within the sandbox (`get_case`, `get_evidence`, `get_shap`, etc.).
3. **Report:** Synthesizes the evidence-grounded assessment narrative.
   - Every citation (e.g. `[E1]`) is interactive. Clicking a citation badge switches to the Evidence Binder tab and smoothly scrolls to and highlights the referenced evidence record.
   - Evaluates groundedness score ($0.0 - 1.0$) via `ClaimValidator`.
   - Segregates unsupported claims into a warning container.
   - Provides an interactive **Claim Grounding Sandbox** allowing analysts to validate arbitrary statements live against case evidence.

## 6. Court-Ready Binary Evidence Pack Export

Analysts can download an official cryptographic ZIP evidence bundle directly via `GET /api/v1/cases/:id/evidence-pack`:
- **`manifest.json`**: Contains SHA-256 hashes of all bundled files.
- **`case_summary.json`**: Case docket metadata, risk score, and priority.
- **`evidence_records.json`**: Complete dump of all active and withdrawn evidence.
- **`audit_events.json`**: Immutable hash-chained ledger events.
- **`case_transitions.json`**: Chronological state transitions with actor and co-approver signatures.
- **`investigation_report.txt`**: Plaintext export of the latest FinSure Investigator report.
